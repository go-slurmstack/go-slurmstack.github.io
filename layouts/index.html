A teaching cluster should take one command to build and one to tear down. slurmstack creates the network, the router, the floating IP and the servers with Terraform, then configures munge, NFS and Slurm with go-ansible's engine, in process — no Python, no ansible-playbook to install. Why slurmstack

The first connection is verified, not trusted.

Most deployers turn host key checking off, because a server that did not exist a minute ago has no key anyone could know. It does: cloud-init prints it on the console, and the cloud API hands the console to the project's owner over HTTPS.

🔑

Host keys from the console

Before connecting, slurmstack reads each server's console log through the OpenStack API, takes the keys between cloud-init's markers and writes the only known_hosts the playbooks will accept. Nothing is added to ~/.ssh.

🐹

Ansible without Python

The playbooks run on go-ansible's engine, linked into the binary. A test parses them and fails if any task names a module the engine lacks, so the gap shows up in CI and not on a live cluster.

🧭

One public address

Only the frontend has a floating IP. The NFS server and the workers are reached through it, over a jump the connector does itself — go-ansible does not read ansible_ssh_common_args.

🧂

One munge key, kept

The key is generated once into the state directory, mode 0600, and handed to the engine in memory — never on a command line. A re-run gives every node the same bytes, so a rebuilt frontend does not orphan its workers.

📜

An openrc read, not run

The OpenStack credentials come from the openrc file Horizon gives you, parsed rather than sourced. A line that needs a shell is refused, and a prompted password is asked for, never taken as the literal $OS_PASSWORD_INPUT.

🧹

Torn down as easily

destroy refuses without --yes, and task teardown asks first: the volume behind /home goes with the servers.

A cluster that ships like Go.

Terraform and the playbooks are embedded in the binary; the state, the pinned host keys and the munge key live in one directory beside your terraform.tfvars. Every tool comes from pkgx, and every variable — image, flavors, network names, worker count — is a Terraform variable.
